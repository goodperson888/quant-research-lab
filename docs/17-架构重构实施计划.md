# 架构重构实施计划

## 1. 实施原则

采用“目标架构一次冻结 + 功能渐进”的方式：先固定领域协议、安全门禁、Provider/Execution 二维模型和目录边界，再按真实用户路径逐段替换占位。现有数据、文档、配置、Freqtrade runtime、因子注册表和 CLI 不移动、不重写。

## 2. 不可逆决策与可延后决策

Phase 0 冻结：

- 策略优先、baseline 不可覆盖；
- Agent-first hybrid，Web 与 Agent 共用控制平面；
- Agent Provider 与 Execution Target 分离；
- External Agent + local runtime 是第一优先；
- API 只暴露领域白名单；
- HTTP 不运行长回测；
- SQLite Job Registry + append-only AuditEvent；
- OpenAPI 是前后端统一契约；
- 无 live trade、密钥或自动生产晋升。

延后到有证据再决定：

- OpenAI/Ollama/LM Studio 的具体 adapter；
- MCP Server 实现和 Local Connector 协议；
- Freqtrade Hyperopt 或 Optuna；
- Lightweight Charts、ECharts 的具体封装；
- Hosted Sandbox、云数据库、多租户和计费；
- 是否需要 SQLAlchemy/Alembic。

## 3. Phase 0：产品基础纵切

### 3.1 文档

- PRD、目标架构、实施计划；
- 页面、状态机、API、非目标和验收；
- 红队 kill assumptions 及最低成本验证；
- Agent Provider × Execution Target 二维模型。

### 3.2 Python 分层

- `domain/`：ResearchSession、StrategyDraft、StrategyVersion、AgentRun、ExperimentPlan、Trial、Job、Report、AuditEvent 等；
- `application/`：会话、intake、freeze、Job 用例；LLMProvider 和 ResearchToolGateway 端口；
- `infrastructure/`：SQLite Repository、数据/项目只读器、未配置 LLM adapter、旧因子注册表适配；
- `interfaces/api/`：FastAPI/OpenAPI；
- `interfaces/cli/`：兼容入口；
- `workers/`：无默认 Handler 的白名单 Worker 壳。

### 3.3 产品状态数据库

路径 `runtime/app/quant_lab.sqlite3`，Git 忽略。首版 schema 包括 sessions、messages、drafts、ambiguities、proposals、versions、approvals、jobs、job_logs、reports、audit_events。AuditEvent 由 Trigger 拒绝 UPDATE/DELETE。

### 3.4 Web

- `/` 重定向 `/studio`；
- Studio 三栏体现会话/Agent Run、对话、结构化成果；
- 实际保存 ResearchSession、Message、StrategyDraft 和 baseline；
- 展示 Agent Provider、Execution Target、连接状态和未配置 Provider；
- 其他页面读取真实 API 或明确占位。

### 3.5 开发体验

- `scripts/dev-api.sh`：仅 `127.0.0.1`；
- `scripts/dev-web.sh`：本地 Next；
- `scripts/dev-worker.sh`：输出当前 Worker 能力，不常驻、不伪执行；
- Makefile 提供相应目标；
- Python 与 Node 依赖精确锁定。

## 4. Phase 0 验证矩阵

| 风险 | 验证 |
|---|---|
| 破坏旧 CLI | 旧测试 + `python -m quant_lab.cli doctor` |
| baseline 被覆盖 | 第二次 freeze 必须 409/Conflict |
| Agent 静默修改 | 无 baseline UPDATE API；Proposal 仅为 draft |
| 无边界参数搜索 | ExperimentPlan 缺预算/切分/成本/目标不得 approved |
| 任意命令执行 | Job 类型和 payload key 白名单测试 |
| 误启动实盘 | `scripts/freqtrade.sh trade` 返回 3 |
| API 安全回归 | OpenAPI 不含 trade/live/shell/credential |
| 黑盒 AI | AuditEvent + Agent status + Studio 时间线 |
| 假 AI | UnconfiguredLLMProvider 明确 503/未配置 |
| 前端契约错误 | Next build + lint + typecheck |

## 5. Phase 1：首个真实 baseline

前置条件：用户提供第一份真实自然语言或 Pine 策略。

1. 完整 intake 元数据和附件安全存储；
2. External Agent 形式化为结构化规则和歧义；
3. 用户确认并冻结 baseline；
4. 解决 Freqtrade exchange metadata 获取或采用安全缓存；
5. 创建真实 backtest Job Handler；
6. 生成不可变 Run manifest、逐笔差异和基准报告；
7. 与参考平台做小窗口逐笔对账。

退出标准：目标用户在不改代码的情况下完成首个 baseline，并能解释主要交易差异。

## 6. Phase 2：单假设实验与观察

- 持久化 ExperimentPlan、AgentRun/Step、ToolCall、Artifact；
- 增加审批、暂停/取消和 SSE 日志；
- 运行单假设消融、样本外和压力测试；
- Web 展示 diff、Trial 表和候选对比；
- 仍不启用大规模搜索或生产晋升。

## 7. Phase 3：受限参数搜索

只有 Phase 1/2 证明用户需要并理解此能力后才进入：

- 选择 Freqtrade Hyperopt 或 Optuna 之一；
- ExperimentPlan 强制 max Trials、时间预算、停止条件和 locked-test 隔离；
- 每个 Trial 写参数、数据版本、指标、状态和日志；
- 分析稳定平台而非历史尖峰；
- 参数搜索必须显式审批，不在对话中逐个盲调。

## 8. Phase 4：Provider 与连接器选择

按用户证据决定优先级：

- External Agent MCP adapter；
- Ollama/LM Studio 本地 Provider；
- 托管 Embedded Provider；
- BYOK；
- 主动出站 Local Connector。

任何 Provider 输出继续是 draft/proposal。Local Connector 不开放用户本机入站端口。

## 9. Phase 5：Hosted Sandbox（条件触发）

仅当存在普通 Web 用户、明确付费意愿和本地安装阻力时评估。必须先设计：租户隔离、策略隐私、数据驻留、密钥托管、审计、资源配额、成本和删除策略。不得直接把本地 SQLite/目录模型搬到共享云主机。

## 10. 数据库迁移策略

Phase 0 使用 `PRAGMA user_version` 和幂等建表。若出现以下任一条件，再评估 Alembic/SQLAlchemy：

- 多个已发布 schema 需要升级/降级；
- Repository adapter 超过一个数据库实现；
- 关系和查询复杂度使手写 SQL 难以审计；
- Hosted Sandbox 需要事务迁移。

在此之前，标准库 sqlite3 更轻、更透明。

## 11. 失败与回滚

- 新代码只在 `feat/product-foundation` 分支；
- 不移动数据和 runtime，因此回退代码不会影响权威 Parquet；
- 产品 SQLite 是新建且 Git 忽略，可备份后重建；
- 旧 CLI、factor registry、runs 模块保留兼容入口；
- 网络依赖失败必须报告，不用未验证版本或绕过镜像；
- Worker 没有 Handler 时保持 Job queued，不标 succeeded；
- Embedded Provider 未配置时明确失败，不生成占位策略结论。

## 12. Phase 0 完成定义

- 代码、文档、OpenAPI、Studio 和开发脚本均落盘；
- 历史测试与新增安全/领域/API 测试通过；
- doctor、API smoke、Freqtrade 拒绝 trade 通过；
- 前端 lock、build、lint、typecheck 通过；
- README 和文档地图可找到新文档；
- 无大数据、数据库、环境、日志或密钥进入 Git；
- 提交并推送功能分支，不合并 main；
- 明确记录未实现的 AI、Worker Handler、MCP、优化器和云能力。
