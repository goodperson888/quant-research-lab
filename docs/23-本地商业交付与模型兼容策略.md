# 本地商业交付与模型兼容策略

状态：产品决策已冻结，Local Connector、BYOK、离线授权及 Windows/macOS 打包骨架已实现
更新日期：2026-08-03

## 1. 商业首版定位

商业首版交付“单用户、本地优先、策略优先”的量化研究工作台：客户在自己的机器上
运行安装包或受管容器，通过浏览器使用 Web Studio。建议商业模式为订阅许可证，并可选
提供一次性部署、迁移和培训服务。早期先以少量付费试点验证安装、首个 baseline、研究
严谨性和支持成本。当前先使用人工转账与离线签名许可证，不立即建设自动支付、联网账号、
代码混淆或自动更新系统。

交付的是可安装产品，不是 Git 仓库。产品源代码、提交历史和内部开发工具不属于默认
客户交付物。闭源只能提高复制和修改门槛，不能保证软件不可观察、不可调试或不可逆向；
产品价值必须来自可靠工作流、可审计证据和持续服务，而不是把“无法逆向”当作承诺。

## 2. 客户数据与许可证到期

- 市场数据、策略原文、实验、报告和 Provider Key 默认留在客户机器；
- 客户研究资产使用可导出、可备份的项目格式，不被许可证机制锁住；
- 许可证到期后进入只读、可查看、可备份、可导出模式；禁止删除、加密扣留或阻止客户
  取回已有数据；
- 到期后可停止创建新研究、启动新 Job 或调用付费能力，但必须清楚区分“功能停用”和
  “客户数据所有权”；
- 当前阶段已实现 Ed25519 离线许可证、设备绑定和到期只读；没有自动支付、联网账号、
  自动更新、遥测或远程停用实现。

## 3. 部署形态

首版已实现 Windows x64 与 macOS 本地安装包构建骨架，包含项目自有 Native Engine、
FastAPI、Worker、Web Studio 和必要的开源运行依赖。默认监听本机回环地址，不要求把
客户机器暴露到公网。数据、SQLite、日志和 Provider Key 不打包回传。受管容器仍是后续
候选，不属于当前 MVP。

受管容器不等于云服务：它仍在客户控制的机器或私有环境运行。未来若提供 Hosted
Sandbox，必须另行解决多租户隔离、数据驻留、密钥托管、计费、配额、审计和删除策略，
不能沿用本地单用户假设直接上线。

## 4. Native Engine 与 Freqtrade 商业边界

Native Engine 是商业产品默认、可独立运行的核心研究引擎。未安装 Freqtrade 时，策略
收录、baseline、smoke、fast screen、成本敏感性、实验注册、报告和本地治理仍应工作。

Freqtrade 保留为可选 external engine，用于第二引擎对账、合适阶段的 full validation
或未来 dry-run 准备。边界如下：

- 由客户自行选择并单独安装；
- 通过独立进程、受限 CLI 和标准文件协议连接；
- 商业包不捆绑、复制或修改 Freqtrade；
- 项目核心业务代码不得直接 `import freqtrade`；
- adapter 只做能力检测、输入输出映射和安全拒绝，不提供任意 Shell 或 `trade`；
- 缺少 Freqtrade 时必须报告 optional engine unavailable，不能阻塞 Native 核心流程；
- 当前开发环境中的固定版本和 smoke 仅证明工程适配，不代表商业分发方式。

Freqtrade 当前标注为 GPL-3.0。其对具体分发、进程边界、协议、组合方式及客户安装流程的
影响属于工程与法律审查事项；本文不作法律结论。任何正式收费和商业分发前，必须由具备
开源许可证经验的律师复核最终制品、安装器、依赖清单、用户协议和交付流程。

## 5. 模型能力门禁

机器可读契约位于 `configs/agents/agent-manifest.json`，策略标识为
`capability_gated_modern_models_only`。所有 Embedded/BYOK 模型只有同时满足下列能力才
允许配置：

- 原生 tool calling；
- JSON Schema structured output；
- 多轮 tool results；
- 至少 32K context；
- 明确的指令层级；
- 中文和英文。

不兼容 chat-only 模型、提示词模拟工具、依赖 free-text JSON 修补的模型，也不允许在
失败时静默降级到弱模型。Provider adapter 只归一化厂商请求、响应和流式事件，不得改变
`ResearchToolGateway`、审批门禁、baseline 不可变规则、Job 白名单或实盘禁令。

当前首个 adapter 是 `openai_compatible`，已用于策略形式化的 JSON Schema vertical
slice；Anthropic 和 Gemini 仍根据真实客户需求后续决定。当前实现会在响应阶段验证
结构化输出和 `requires_user_confirmation=true`，但尚未实现跨厂商通用 Agent tool loop。

## 6. Provider Key 策略

本阶段提供本地网页 Key 录入，但 Key 只保存在 API 进程内存。页面不使用
`localStorage`/`sessionStorage`，API 不写 Git、项目配置、SQLite、日志、Audit payload，
也不回显 Key、片段或哈希；API 重启后配置自动清空。本地后续可增加 OS Keychain，云模式
只允许经过访问控制、加密和审计的 Secret Manager。

## 7. 当前已实现与未实现

已实现的是模型能力 manifest、内存 BYOK 配置、OpenAI-compatible JSON Schema 形式化、
Local Connector、真实 AgentRun 状态、Freqtrade external-engine 代码边界、离线签名
许可证、设备码、人工签发/续费、设置页导入、后端写操作门禁，以及 Windows/macOS
原生商业包构建骨架。尚未实现：Windows Authenticode、Apple Developer ID 公证、平台
托管 Provider、通用模型工具循环、账号订阅、自动支付、受管容器、自动更新、远程吊销、
Hosted Sandbox、多用户和商业遥测。任何演示不得把这些规划项描述成已经可用。

## 8. 商业试点验收

正式扩大销售前至少验证：客户无需开发者介入完成安装和首个 baseline；Native Engine
在没有 Freqtrade 时可完成核心研究闭环；许可证到期演练保留只读和导出；卸载不删除客户
数据；模型不满足 manifest 时明确拒绝；Provider Key 不出现在浏览器持久存储、仓库、
SQLite 和日志；律师已复核最终开源依赖与分发方式。
