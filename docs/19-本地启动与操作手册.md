# 本地启动与操作手册

## 1. 安全边界

本手册只用于本地历史研究、报告和 dry-run 准备。API 和 Web 都没有 live trade、
任意 Shell 或自动 production 晋升接口。网页模型 Key 只允许进入 API 进程内存；不要在
任何项目文件中填写交易密钥或模型 Key。

## 2. 首次安装与检查

```bash
cd /Users/laochen/Documents/lianghua/quant-research-lab
./scripts/bootstrap.sh
./scripts/doctor.sh
```

`bootstrap.sh` 把 uv、Python 3.12、`.venv` 和缓存留在项目目录。`doctor.sh` 应显示
Python 3.12、注册表和产品 SQLite 已就绪，且 `live_trading_enabled=false`。

## 3. 启动 API、Web、Worker 和 Local Connector

推荐直接使用一行命令：

```bash
cd /Users/laochen/Documents/lianghua/quant-research-lab
./scripts/dev.sh
```

该脚本同时启动 API、Web、单并发后台 Worker 与 Local Connector，并直接打印正确地址：

- Web Studio：`http://127.0.0.1:3100/studio`
- API health：`http://127.0.0.1:8100/health`
- API OpenAPI：`http://127.0.0.1:8100/docs`

开发模式默认开启热更新：

- `apps/web/` 下的 Next.js 页面、组件和样式修改后自动刷新；
- `src/quant_lab/` 下的 Python API 修改后由 Uvicorn 自动重载；
- Worker 进程由 `dev.sh` 管理；修改 Worker/Handler 代码后执行一次 `dev.sh restart`；
- Local Connector 进程由 `dev.sh` 管理；修改其 Python 代码后执行一次 `dev.sh restart`；
- 日常代码修改不需要重复执行 `dev.sh restart`；
- 只有安装/删除依赖、修改启动脚本、端口或环境变量时才需要重启。

极少数受限容器不允许 Uvicorn 创建重载子进程，可临时使用
`QUANT_LAB_API_RELOAD=false ./scripts/dev.sh`；普通 macOS 本地终端保持默认热更新即可。

`dev.sh` 是单实例入口。重复执行时，如果状态文件完整，会打印“已经运行，可直接访问”。
如果检测到本项目手动启动的服务、以前由其他 AI 窗口启动的服务，或运行状态文件丢失，
脚本会严格核对命令和工作目录，先正常停止旧实例，再重新纳入统一管理。常用管理命令为：

```bash
./scripts/dev.sh stop
./scripts/dev.sh restart
./scripts/dev.sh status
```

`stop` 优先停止同时匹配 PID、项目服务角色、项目目录和本次实例标记的进程组。状态文件
丢失时，只对当前端口上能够同时确认“服务角色 + 本项目工作目录”的监听进程发送
SIGTERM；如果同一 PID 在等待期后仍占用端口，脚本会再次核对 PID、服务角色和项目目录，
确认身份没有变化后才使用 SIGKILL 清理卡死的旧开发进程。没有足够证据时宁可拒绝停止，
也不会终止其他软件。`restart` 先执行同样的安全停止，再重新启动。
PID、端口和实例状态保存在 `runtime/dev/state.json`，该目录不进 Git；陈旧或损坏状态会
在端口预检后安全清理。

在前台启动终端按 `Ctrl+C` 会同时停止 API、Web、Worker 和 Local Connector。如果任一服务启动失败或启动期间端口
发生竞态，脚本会关闭本次已经启动的另一服务，避免留下后台进程。多个窗口同时启动时，
文件锁只允许一个窗口执行启动流程，其余窗口等待后复用已有实例。

`dev-web.sh` 默认启用 Watchpack polling，避免 macOS 在项目依赖较多时触发
`EMFILE: too many open files` 并导致开发页全部显示 404。若确认本机文件监听上限充足，
可临时使用 `WATCHPACK_POLLING=false ./scripts/dev-web.sh`。

需要分别观察日志或排错时，也可以分别运行：

```bash
./scripts/dev-api.sh
./scripts/dev-web.sh
./scripts/dev-worker.sh --watch
```

打开 `http://127.0.0.1:3100/studio`。不要把 API 的 `8100` 端口当作网页首页。
Studio 展示 Agent 状态、Pipeline Profile、门槛、
StrategyOutcome、组件分流、regime 证据和 Pine 验证阶段。Local Connector 离线或网页
Provider 未配置时不会伪造 AI 回复：输入会明确保存为策略原文或研究指令，页面只使用
真实状态与确定性规则分析器生成中文说明。本地 AI 与网页模型共用同一结构化计划、工具白名单、审批
门禁和审计事件，差别只在 Provider 与展示入口。

Studio 的首屏顺序是“当前结论与下一步 → 问题归因 → 最多三个改进方向 → 批量参数进度
→ 资金曲线/回撤/指标对比 → 研究助手总结”。资金曲线只读取已登记的项目相对 Parquet
Artifact；缺少 Trial 曲线时页面明确说明，不用指标伪造曲线。

走势页的行情K线周期只列出本次运行数据清单中真实存在的 5m、15m、1h、4h 数据。
切换周期只改变观察粒度，不会修改已经产生的交易和资金曲线。全区间细周期数据超过
浏览器展示上限时，服务端按 OHLCV 规则确定性聚合，并在图表标题中明确标注实际展示
粒度。资金曲线工具栏中的“全周期”会恢复完整覆盖范围。

当前自动回测使用下载到本地、具有版本号和数据清单的市场数据，以保证结果可复现。
网页中的 TradingView Lightweight Charts 只负责K线和资金曲线展示；TradingView 网站
及 Pine Strategy Tester 不属于当前自动回测引擎。Pine 可在可行性通过后用于语义检查、
代表交易核对和最终平台对账，但不替代本地可审计回测。

左侧“策略与因子”进入统一研究资产库，分别展示：

- 原始策略、冻结基准、候选版本和已验证结论；
- 研究过程中沉淀的诊断组件与 component candidate；
- 独立因子注册表及其市场隔离状态。

组件候选不自动等于已验证因子；页面会明确显示当前各层资产数量和证据级别。

## 4. Worker 队列与单次排错

```bash
./scripts/dev-worker.sh
```

无参数时，命令只打印 `execution_mode=one_shot_or_watch`、已注册 Handler 和安全状态，
以及 `configs/workers/local.yaml` 的 RSS、Job 时间、并发和 Parquet batch 预算，然后立即
退出。

常驻本地队列使用：

```bash
./scripts/dev-worker.sh --watch
```

它按创建时间领取自己能够处理的 queued Job，始终单并发；未知 Job 保留在队列，不执行、
不调用 Shell。单个 Job 失败会写日志、Handoff 和 audit，然后继续轮询。

只有 API/CLI 先创建白名单 Job 后，才使用：

```bash
./scripts/dev-worker.sh --job-id job_xxx
```

`--job-id` 一次只执行一个 Job 并退出，适合排错。两种模式都不接受任意命令。Full stress 还会复查
同一 strategy version 的 passed viability gate；正式 regime validation 同样复查同一
subject 的 viability。资源超限 Job 标记 failed 并保留日志/audit，不删除已有 Artifact。

## 5. 首个策略输入流程

“策略原文”指用户最初想到、听到、复制或编写的内容，可以是不完整的自然语言，也可以是
完整 Pine Script；它不是已经可运行的策略代码。

产品最终保留三种入口：

1. **直接在 Codex/Claude CLI 研究**：在本地 Agent 中描述策略 →
   Agent 创建/读取同一 Session 和 Draft → 与用户确认经济含义歧义 → 写回结构化结果与
   受测执行器 → 用户在网页审批和查看结果。
2. **网页调用本地助手**：选择该入口后粘贴策略，点击“交给本地 Codex”；独立 Local
   Connector 领取 AgentRun，页面显示排队、运行、待确认或失败。
3. **网页模型/API Key**：选择该入口后，在页面配置 provider、Base URL、模型 ID 和 Key；
   Key 只在当前 API 进程内存，配置成功后点击“交给网页模型”。

网页入口的标准步骤：

1. 选择 Local Connector 或网页模型；
2. 输入标题、内容类型和策略原文；
3. 提交后系统原子化创建 ResearchSession/StrategyDraft/AgentRun；
4. 页面每 2 秒同步 AgentRun，AI 写回结构化提案后状态变为“等待你确认”；
5. 在网页审阅结构化规则和歧义，再单独批准冻结 baseline v0；
6. 选择 `smoke`、`fast_screen` 或 `full_validation`，点击“授权并开始研究”；
7. Worker 按 correctness → smoke → fast screen → viability 执行；“少亏”只记为
   diagnostic improvement，只有 viability 通过后才进入 regime/Pine、锁定测试和 full stress。

未形式化 Draft 不再预填伪结构化 JSON，也不能冻结 Baseline。用户也可以完全跳过网页建档，
直接在 Codex 描述策略；三种入口最终写入同一 SQLite、Artifact 和审计状态。

## 6. 图表阅读规则

- 只有标的、回测时间区间、初始资金和成本假设可比的资金曲线，才允许在同一坐标轴上
  多选叠加。不同日期的训练、验证和小范围试跑结果必须逐条查看，不能冒充多策略对比。
- 新参数批次为每个成功 Trial 保存验证区间的真实压缩资金曲线，默认最多约 500 点；同一
  flush 的 Trial 合并写入一个 Parquet，SQLite 只保存 Artifact key，不创建一 Trial 一个
  大文件。旧批次没有曲线时明确提示重新运行，不从汇总指标伪造。
- 参数页默认勾选最多 6 个代表方案（原样/收益代表、回撤代表、Profit Factor 代表和中位
  代表），用户可切换，但只有时间覆盖一致的曲线才允许同图叠加。完整 Baseline 和最终关键
  Candidate 仍按保留策略保存完整 equity；普通 Trial 只保留压缩曲线。
- 历史交易图选择具体交易后，读取该交易附近的原周期 K 线；入场、止损和止盈显示为
  三条计划价格线，离场显示为成交点，不画成贯穿整张历史图的永久价格线。
- 行情交易图分为“完整回测走势”和“逐笔交易复盘”。完整回测走势展示整个回测区间及
  全部交易点；点击交易点或进入逐笔复盘后，才读取该笔交易附近的原周期 K 线。
- 行情周期支持 5 分钟、15 分钟、1 小时、4 小时和日线。日线不另造数据，由本次运行
  已登记的小时线按 UTC 自然日确定性聚合。
- 当同一研究结果同时保存训练与验证资金曲线时，页面额外提供“完整研究周期资金曲线”，
  按时间顺序衔接两段真实曲线。该概览只用于浏览完整周期，训练与验证指标仍独立计算。
- 行情 K 线和交易点使用 TradingView Lightweight Charts；资金曲线使用 ECharts，
  默认展示完整日期范围，并用底部时间滑块缩放。选择一条资金曲线后，行情和交易点自动
  跟随其所属回测结果，不再要求重复选择同一份运行。
- 资金曲线和参数图必须同时提供表格或数值摘要；当曲线只有极少资金变化时，页面会明确
  提示折线信息有限，避免把稀疏阶梯误读成持续走势。

## 7. 停止

- 使用 `dev.sh` 时，在同一终端按一次 `Ctrl-C` 即可同时停止 API、Web、Worker 与
  Local Connector。
- 在其他终端运行 `./scripts/dev.sh stop`，可停止托管实例，也可恢复停止能严格确认属于
  本项目的旧实例。
- 需要重启时运行 `./scripts/dev.sh restart`，无需手工查找 PID。
- 日常修改 Web/Python 源码无需重启；保存文件后等待自动刷新即可。
- 分开启动时，在 API/Web 各自终端按 `Ctrl-C`。
- Worker 正常会在单个 Job 完成或失败后自行退出。
- 不要用 `kill -9` 作为常规停止方式；先保留 Job 日志和部分 Artifact。

## 8. 排错

- API 不通：运行 `./scripts/doctor.sh`，再检查 `curl http://127.0.0.1:8100/health`。
- 端口占用：直接运行 `./scripts/dev.sh status` 查看端口、PID、进程命令和工作目录。
  如果是本项目旧实例，直接运行 `./scripts/dev.sh start` 重新纳管，或运行
  `./scripts/dev.sh stop` 安全停止。未知进程只会被报告，不会被停止；也可用
  `QUANT_LAB_API_PORT=<空闲端口> QUANT_LAB_WEB_PORT=<空闲端口> ./scripts/dev.sh`
  临时改端口。
- 状态异常：运行 `./scripts/dev.sh status`。`runtime/dev/` 仅保存本地开发运行态，可以
  在确认相关服务均已退出后删除；不要凭陈旧 PID 手工终止进程。
- Web 显示空态：确认 API 已启动，且 `NEXT_PUBLIC_QUANT_LAB_API_URL` 没有指向其他主机。
- Job 一直 queued：确认是否已显式执行 `dev-worker.sh --job-id ...`。
- 本地 AI 一直 queued：运行 `./scripts/dev.sh status`，确认 Local Connector 已启动；
  再检查 `/api/agent/status` 的 heartbeat 和 Codex CLI 检测状态。
- 网页模型配置消失：这是预期安全行为；API 重启会清空内存 Key，需要重新配置。
- Full stress 被拒绝：查看同一 subject 的 viability gate ID，不要伪造通过状态。
- Pine 对账未开始：这可能是正常 fail-fast；完整诊断在 viability 后。
- Freqtrade 市场 metadata 直连超时：保留失败日志；如用户明确提供本机代理，可用临时
  overlay 的 `aiohttp_proxy` 做公开 metadata smoke，不把代理写入仓库或环境文件。
- funding/mark/index/OI 缺口：查看年度 manifest，不得静默填 0 或用未来值补齐。

只读治理检查：

```bash
PYTHONPATH=src .venv/bin/python -m quant_lab.cli storage-report
PYTHONPATH=src .venv/bin/python -m quant_lab.cli list-backtest-engines
./scripts/freqtrade.sh list-data \
  --config configs/freqtrade.binance.eth.futures.json \
  --datadir runtime/freqtrade/user_data/data/binance
```

`storage-report` 不删除文件。引擎列表只声明能力，不运行回测；Freqtrade `list-data` 只读
检查本地数据容器。

## 9. 数据和状态备份

大数据不进 Git。关闭 API/Worker 或确认没有写入后，备份：

- `data/raw/`、`data/processed/` 和 `data/manifests/`；
- `runtime/app/quant_lab.sqlite3`（以及存在时的 WAL/SHM）；
- `factor_library/registry.sqlite3`；
- `experiments/runs/`、`reports/`和策略源码。

建议至少“本机 + 外接盘 + 异地”。恢复后先运行 doctor、pytest 和数据 manifest 校验。

## 11. 当前网页完整操作路径

1. 运行 `./scripts/dev.sh start`，打开 `http://127.0.0.1:3100/studio`；
2. 点击“新建研究”，页面自动优先选择在线 Local Connector，其次是已配置网页模型；
3. 输入策略，审阅结构化规则、歧义和“是否可执行”；
4. 冻结 Baseline，点击“授权研究到 Viability”；
5. 在“诊断与优化 → 改进方案”审阅参数数和分钟预算；
6. 点击“批准并运行 N 个方案”，自动创建 Candidate、Plan 和后台 Batch；
7. 在参数页查看全部结果和同区间资金曲线；
8. 若出现稳定区间，可点击“运行有界候选验证”；
9. 候选验证通过后，在“结论与归档”单独点击“批准并运行最终保留测试”；
10. 在“一页研究结论”查看最终判断、最弱证据、行情适配和下一步；报告页可进入单份
    报告查看关键指标与真实资金曲线。

最终保留测试只运行冻结候选和冻结参数，并消耗一次会话额度。查看后不要针对该保留区间
继续调参；如需修改策略，应建立新的研究假设和新的保留期。

后台任务失败时先阅读中文停止原因。页面出现“确认修复后重试原范围”时，重试不会扩大
预算或查看 locked test；如果旧任务已有阶段证据或授权已失效，页面会要求回到工作台重新
授权，而不是静默重跑。

切换研究会话时页面会回到该会话推荐阶段。开发服务支持 Web/Python 热更新，普通修改无需
反复手工重启。
