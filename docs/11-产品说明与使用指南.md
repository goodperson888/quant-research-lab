# 产品说明与使用指南

## 一句话定位

Quant Research Lab 是一个面向个人研究者的、轻量、策略优先、可复现的本地量化研究
工作台。

它帮助用户把一句策略想法、Pine Script 或公开规则，转成可审计的基准策略、实验记录、
样本外证据和可复用组件，同时默认阻止未经批准的实盘行为。

## 目标用户

本项目适合：

- 希望系统研究自己交易想法的个人交易者；
- 希望把 TradingView Pine Script 转换为 Python/Freqtrade 的用户；
- 需要保存策略版本、失败实验和验证证据的研究者；
- 希望未来由 Codex 协助执行数据检查、回归测试和研究记录的人；
- 不希望一开始就维护数据库集群、因子工厂或机器学习平台的小团队或个人。

用户不需要先会 Python，也不需要先知道完整的量化研究术语。可以先提供自然语言或原始
Pine Script，由收录模板逐步补齐规则和歧义。

## 解决的问题

个人策略研究常见的问题不是“缺少更多指标”，而是：

- 原始策略没有保存，优化后无法知道最初规则；
- 一开始就调参数，难以判断利润来自逻辑还是过拟合；
- 数据来源、时间范围、费用和滑点没有固定；
- 看过测试集后继续修改，却仍把结果称为样本外；
- 成功结果被保存，失败实验被遗忘；
- 同一个因子被直接搬到不同交易所、周期或市场；
- 回测、报告、脚本和数据散落在不同目录；
- 研究工具意外连接到真实账户。

本项目用统一收录、冻结基准、一次一个假设、不可覆盖实验、按市场隔离验证和安全包装器
来解决这些问题。

## 核心价值

1. **策略优先**：从真实策略问题出发，因子和组件随研究自然沉淀。
2. **可复现**：固定代码、数据、参数、成本、时间范围、随机种子和输出路径。
3. **可审计**：保留原始来源、所有版本、失败结果、测试集污染和状态变化。
4. **轻量本地化**：单机 Python、Parquet、DuckDB 和 SQLite，无数据库服务。
5. **市场隔离**：一个市场的验证结论不能自动传播到另一个市场。
6. **安全默认**：默认历史研究，实盘关闭，`trade` 命令受包装器阻止。

## 非目标

本项目：

- 不承诺盈利，不承诺“不亏”；
- 不自动启动实盘、增加杠杆或放大资金；
- 不每天自动发明新策略或盲目重调参数；
- 不建设机构级重型因子工厂、数据湖或集群；
- 不用回测最高净利润代替风险判断；
- 不替代用户对交易逻辑、风险承受能力和生产审批的判断；
- 不把 90 日工程验证数据包装成长期有效性证据。

## 核心对象

| 对象 | 作用 | 主要位置 |
|---|---|---|
| Market Profile | 定义资产、工具、场所、周期、数据和成本语义 | `configs/market_profiles/` |
| 策略收录 | 保存来源、原始描述、模糊点和目标市场 | `configs/strategy-intake.example.yaml` |
| 冻结基准 | 保留未经优化的原样策略版本 | `strategies/`、实验 manifest |
| 研究假设 | 描述本次唯一改进、理由、预算和停止条件 | 策略收录 YAML、实验 manifest |
| 因子/组件 | 可复用的信号、过滤器、仓位、风控或执行模块 | `factor_library/`、`strategies/research/` |
| 实验 Run | 不可覆盖的一次研究运行及其全部上下文 | `experiments/runs/<run_id>/` |
| 验证状态 | 记录策略或因子当前研究生命周期 | YAML、SQLite、manifest |
| 报告 | 数据质量、回测、风险、日报和周报 | `reports/` |

## 主要用户旅程

研究使用配置化 Pipeline Profile，默认遵循 `correctness → fast screen →
viability → cheap sensitivity → regime/Pine → full validation/locked/full stress →
dry-run`。某一门槛失败即停止后续昂贵流程。

### 1. 收录想法

用户可以提供自然语言、Pine Script、公开策略、书籍/文章/视频规则。先复制
[策略收录模板](../configs/strategy-intake.example.yaml)，保存原始来源和原文，不先判断
是否盈利。

### 2. 形式化与歧义处理

明确每个指标的计算时间、入场、出场、止损、止盈、仓位、同根 K 线冲突、数据可得性
和市场限制。对无法确定的规则保留问题、采用解释和备选解释。

### 3. 冻结原样基准

形成 `v0-original` 或等价版本，标记 `frozen: true`。冻结后不能覆盖；所有优化必须创建
新版本并引用基准。

### 4. 选择数据与成本模型

选择明确的 market profile、时间范围和周期。手续费、滑点、资金费率、最小金额、精度
和执行限制必须进入 manifest。缺失数据不得静默按零填充。

### 5. 运行基准回测

先回答“原始策略在固定数据与成本下发生了什么”，而不是立即寻找盈利参数。保存交易
明细、主要指标、失败原因和异常交易样本。

### 6. 单假设改进与消融

每次只验证一个明确假设。例如：“1h 趋势过滤是否减少 15m 策略的震荡亏损”。若一次
加入多个组件，必须分别移除组件做消融，确认各自增量。

### 7. 样本外、Walk-forward 和压力测试

按时间顺序使用训练、验证、锁定测试。测试成本提高、滑点提高、参数扰动、延迟、漏单、
删除最佳交易和不同市场状态。查看锁定测试后修改策略，必须标记污染。

压力测试分为 fast screen 后的 cheap cost sensitivity 和 viability 通过后的
full stress。完整策略如果只是“少亏”，不会进入 strategy candidate；局部规则
可在独立证据下保留为 diagnostic/component candidate。

### 8. 沉淀组件

只有加入基准后产生稳定样本外增量的因子、过滤器、仓位或风控组件才保留。别人提供的
因子默认只是 `candidate`。

### 9. 进入 dry-run

候选策略通过样本外、成本和压力测试后，才能进入模拟盘。比较真实信号时间、成交、
滑点和回测差异。

### 10. 人工生产门禁

`production` 必须由人明确批准具体交易所、账户、策略、资金上限和时间窗口。自动任务
无权完成该晋升。

## 状态机

| 状态 | 含义 |
|---|---|
| `inbox` | 已收录原始想法，尚未形式化 |
| `formalized` | 规则已无歧义，但尚未冻结基准 |
| `baseline` | 原样基准已冻结并完成基准实验 |
| `candidate` | 存在待验证的策略或组件假设 |
| `validated` | 在指定 market profile 通过样本外、成本和压力测试 |
| `dry_run` | 正在模拟盘观察信号和执行偏差 |
| `production` | 人工批准后在明确边界内使用 |
| `degraded` | 已验证结论出现衰减，暂停晋升并复核 |
| `retired` | 已停止使用，但保留全部历史 |
| `rejected` | 验证失败，保留失败原因和证据 |

状态必须按 market profile 隔离。Binance 15m 的 `validated` 不代表 OKX、股票或其他周期
也已验证。

## 日常工作节奏

### 每日监控

- 数据完整性、时间范围和异常价格；
- 已有因子健康度；
- 已有策略滚动样本外表现；
- 回撤、滑点、成交和信号异常；
- 生成日报和风险提示。

每日任务不得重调生产参数，不得自动发明或晋升策略。

### 有新想法时

创建独立策略收录和研究任务，冻结基准后再开始实验，不混入日常监控。

### 定期复核

检查策略相关性、共同尾部风险、衰减、容量、换手和组合贡献；失效策略不能被组合总收益
掩盖。

## 用户输入模板

用户最简单可以这样输入：

> 当 15m 收盘价上穿过去 20 根最高价时做多；1h EMA50 向上时才允许入场；止损为
> 2 ATR；反向突破退出。来源是我看到的一段视频，不确定“上穿”是否要求前一根在下方。

也可以直接提供：

```text
来源：TradingView Pine Script
目标市场：ETH/USDT 永续
期望执行周期：15m
方向：只做多/只做空/双向
原始代码：...
已知疑问：...
```

系统会把这些内容写入策略收录模板，不会立即优化。

## 典型命令

检查环境和注册表：

```bash
./scripts/doctor.sh
PYTHONPATH=src .venv/bin/python -m quant_lab.cli init
PYTHONPATH=src .venv/bin/python -m quant_lab.cli list-factors
```

重新生成当前数据查询层和 Freqtrade 本地格式：

```bash
.venv/bin/python scripts/export_freqtrade_data.py
.venv/bin/python scripts/build_data_catalog.py
./scripts/freqtrade.sh list-data \
  --userdir runtime/freqtrade/user_data \
  --datadir runtime/freqtrade/user_data/data/binance \
  --data-format-ohlcv parquet \
  --trading-mode futures --show-timerange
```

运行测试：

```bash
.venv/bin/python -m pytest
```

不要直接运行 `freqtrade trade`；项目包装器默认阻止该命令。

## 输出物

一次完整研究可能产生：

- 原始策略档案和形式化规则；
- 冻结策略源码与版本；
- 数据 manifest、质量统计和校验和；
- 实验 manifest、命令、参数和日志；
- 交易明细、QuantStats/HTML 报告和风险摘要；
- 样本外、Walk-forward、消融和压力测试结果；
- 因子/组件的市场适用性与状态；
- dry-run 偏差报告和人工审批记录。

## 安全、密钥和实盘边界

- 历史公共数据不需要交易密钥。
- 密钥、Cookie、密码和提现凭据不得进入项目或 Git。
- 永不请求或使用带提现权限的交易所密钥。
- `scripts/freqtrade.sh` 默认拒绝 `trade`。
- 自动任务无权启用实盘、增加杠杆、扩大资金或晋升生产。
- 实盘必须明确批准交易所、账户、策略、资金上限和时间窗口。

## FAQ

### 90 天数据足够吗？

足够验证数据管道、基准流程和进行候选初筛，但不足以覆盖完整牛熊周期、长期资金费率、
极端行情和交易所故障。出现候选后必须扩展历史和市场状态。

### 因子是否可以跨市场通用？

因子思想可能通用，验证结论不通用。同一公式必须按资产类别、工具、场所、周期和成本
重新验证。

### 为什么不每天自动优化？

每日优化会不断适配最近噪声，增加过拟合和参数漂移。每日任务应监控，研究任务才验证
预先声明的假设。

### 为什么不能保证不亏？

历史数据不能穷尽未来市场状态，模型还受到滑点、流动性、执行、制度变化和基础设施
故障影响。项目提供证据和门禁，不提供收益保证。

### 为什么保留失败实验？

失败记录可以防止重复踩坑、事后挑选结果和选择性汇报，也是判断哪些逻辑不适用的重要
研究资产。

### 当前可以直接回测第一份策略吗？

已有一份价格结构 baseline 和本地确定性回测证据。Freqtrade 需实时
`exchangeInfo` 的完整引擎流程仍可能受网络超时影响，但不再影响收录、
基准、门槛和本地研究记录。

### 第一份真实策略在哪里？

用户已提供“高点和低点上移做多，反之做空”的 ETH/USDT 永续日内规则。
baseline v0 仍冻结；入场确认改进在成本压力下失败，完整策略版本已被人工标记
`rejected`。该失败证据保留，局部入场改进只能作为 diagnostic/component 证据，
不是可交易候选。
