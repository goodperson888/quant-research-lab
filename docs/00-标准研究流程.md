# 标准研究流程

## 目标

证明策略不是数据错误、代码错误或历史过拟合，并确认它在真实成本和执行约束下仍具有研究价值。

## 配置化 Fail-fast 顺序

每次研究先选择 `configs/pipelines/` 中的 `smoke`、`fast_screen` 或
`full_validation`，再按以下顺序执行：

`correctness → fast screen → viability → cheap sensitivity → regime/Pine → full validation/locked/full stress → dry-run`

`viability` 是独立的完整策略门槛，不等于代码正确或相对 baseline 少亏。
门槛失败后停止昂贵验证，只允许廉价归因和组件证据分流，不得继续盲调。
阈值属于 Pipeline Profile + Market Profile + strategy objective，不是跨市场定理。

## 十阶段流程

1. **研究假设**：先写清经济逻辑、交易对象、信号、周期、订单和风险规则。
2. **数据审计**：检查缺失、重复、异常、时区、未来数据、多周期对齐和交易所差异。
3. **代码验证**：单元测试指标、仓位、止损、手续费和边界情况；人工复核代表性交易。
4. **基准回测**：固定原始参数，保存第一份不可覆盖的基准结果。
5. **时间切分**：训练、验证、锁定测试按时间顺序划分，禁止随机打乱。
6. **参数研究**：只在训练和验证区间进行，寻找稳定平台而不是最高尖峰。
7. **样本外验证**：运行 Walk-forward，并比较多个市场阶段和资产。
8. **压力测试**：提高成本、增加延迟、扰动参数、删除最佳交易、执行 Monte Carlo。
9. **模拟盘**：核对真实信号、延迟、成交和回测差异。
10. **小资金上线与监控**：人工批准后逐级放量，设置硬性熔断与回滚。

## 五道硬门槛

以下任意一项失败，策略不得进入实盘：

1. 数据正确；
2. 代码正确；
3. 样本外有效；
4. 成本和压力测试存活；
5. 模拟盘与回测差异可解释。

## 实验记录要求

每次运行必须记录：

- 运行编号和时间；
- 策略/因子代码版本；
- 数据来源、版本和时间范围；
- 参数、费用、滑点和资金费率；
- 训练、验证、测试切分；
- 随机种子；
- 输出文件和主要指标；
- 是否通过验收；
- 失败原因和下一步假设。

失败实验不得删除，因为它们用于防止重复研究和选择性汇报。
