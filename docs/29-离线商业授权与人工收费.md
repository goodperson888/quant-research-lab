# 离线商业授权与人工收费

状态日期：2026-08-03

## 1. 目标与边界

第一版商业授权采用“人工转账 → 设备码 → 离线签名许可证 → 本机验证”。客户不需要账号、
VPN、Cloudflare 或持续联网。许可证只控制是否可以创建新的研究状态；到期、设备不匹配或
签名异常时，已有研究结果仍可查看和导出，任何本地数据都不会被删除。

当前实现包含：

- Ed25519 数字签名；
- 设备哈希绑定；
- 30/90/365 天或精确日期许可证；
- 套餐和功能权限；
- 本地导入、状态展示和中文失败原因；
- 后端统一写操作门禁；
- 明显系统时间回退检测；
- 签发、续费、验签和设备码 CLI；
- 开发模式与商业强制模式分离。

当前不包含账号密码、在线支付、自动续费、远程吊销、多设备在线管理和自动更新。
Windows/macOS 商业安装包构建骨架已实现，但正式平台代码签名与公证尚未完成。

## 2. 安全模型

许可证是 `.qllicense` JSON 文件，由商家私钥签名。客户端只携带公钥：

```text
商家私钥签发
  → payload + Ed25519 signature
  → 客户导入 .qllicense
  → 本地公钥验签
  → 后端允许或拒绝新的写操作
```

payload 记录：

- `license_id`；
- `customer_id`，应使用内部编号或邮箱别名，不放身份证、手机号等敏感信息；
- `plan`；
- 哈希后的 `device_code`；
- `features`；
- `issued_at`、`not_before` 和 `expires_at`；
- 续费时的 `previous_license_id`。

客户端不保存机器原始 UUID，只展示形如
`QL-AAAAA-BBBBB-CCCCC-DDDDD-EEEEE` 的不可逆设备码。

离线授权不能实现即时远程吊销，也不能绝对阻止专业逆向。月卡/季卡、后端多入口校验、
Nuitka/签名安装包和后续在线账户服务共同提高商业保护强度。当前源码环境变量只是测试
装配方式；把源码直接交给客户无法形成可靠授权。

## 3. 首次生成商家密钥

私钥必须生成在项目仓库外，例如：

```bash
mkdir -p "$HOME/quant-lab-license-admin"

PYTHONPATH=src .venv/bin/python -m quant_lab.cli license-keygen \
  --private-key "$HOME/quant-lab-license-admin/quant-lab.license-private.pem" \
  --public-key "$HOME/quant-lab-license-admin/quant-lab-public.pem"
```

命令拒绝覆盖已有密钥，也拒绝把私钥生成到项目目录。私钥权限为 `0600`。

至少保留两份加密备份：

1. 当前签发电脑；
2. 加密移动硬盘或安全离线介质。

私钥丢失后无法给既有客户端签发可验证续费许可证；私钥泄漏后必须更换公钥并发布新版本。
不要把私钥发到聊天、邮箱、网盘、Git 或客户安装包。

公钥可以复制到商业构建：

```bash
cp "$HOME/quant-lab-license-admin/quant-lab-public.pem" \
  configs/licensing/public-key.pem
```

公钥不是秘密，可以进入最终安装包。是否提交该公钥，应在正式建立商业发行密钥后再决定。

### 3.1 商家换电脑时如何继续签发

卡密不绑定商家的签发电脑。真正的签发身份是长期
`quant-lab.license-private.pem`；客户许可证绑定的是客户发来的 `device_code`。

商家换电脑后，只要迁移以下内容，就能继续给原安装包签发和续费：

1. 原始 `quant-lab.license-private.pem`；
2. 对应 `quant-lab-public.pem`；
3. 不进 Git 的客户台账；
4. 历史 `.qllicense`，用于方便续费和核对授权链；
5. 当前私有项目仓库或以后提供的独立签发工具。

新电脑安装项目依赖后，继续把 `license-issue`/`license-renew` 的
`--private-key` 指向迁移过来的同一私钥即可。签发命令不检查商家电脑设备码，也不要求
使用最初生成密钥的电脑。

迁移前应校验公钥指纹：

```bash
PYTHONPATH=src .venv/bin/python -m quant_lab.cli license-inspect \
  --license "$HOME/quant-lab-license-admin/任意一份历史许可证.qllicense" \
  --public-key "$HOME/quant-lab-license-admin/quant-lab-public.pem"
```

不要在新电脑重新运行 `license-keygen` 来代替迁移。新生成的私钥代表另一套授权身份；
既有客户安装包只内置旧公钥，不会接受新私钥签发的许可证。如果旧私钥丢失且没有备份，
只能生成新密钥、用新公钥重新构建客户端，并让所有客户升级后重新发证。

建议把签发目录做成加密离线备份，而不是普通网盘同步。若必须跨电脑传输，使用加密移动
硬盘、受控密码管理器的文件附件或单独加密归档，并在传输后清除临时明文副本。

## 4. 客户激活流程

客户打开“本地设置 → 本地商业授权”：

1. 点击“复制设备码”；
2. 把设备码和付款使用的客户编号发给商家；
3. 收到 `.qllicense` 文件；
4. 点击“选择许可证”；
5. 点击“验证并导入”；
6. 页面显示套餐、到期时间、剩余天数和功能权限。

也可以在客户电脑读取设备码：

```bash
PYTHONPATH=src .venv/bin/python -m quant_lab.cli license-device-code
```

设备码不包含可直接识别的硬件 UUID。

## 5. 人工转账后签发

收到转账后，商家运行：

```bash
PYTHONPATH=src .venv/bin/python -m quant_lab.cli license-issue \
  --private-key "$HOME/quant-lab-license-admin/quant-lab.license-private.pem" \
  --customer-id customer_001 \
  --plan personal \
  --device-code QL-AAAAA-BBBBB-CCCCC-DDDDD-EEEEE \
  --days 30 \
  --output "$HOME/quant-lab-license-admin/customer_001-202608.qllicense"
```

默认功能权限为：

- `research`；
- `backtest`；
- `batch_trials`；
- `reports`；
- `local_ai`。

也可以重复使用 `--feature` 精确指定权限。许可证价格不写进软件；价格、收款渠道和发票
由商家账务记录管理。

建议维护一个不进 Git 的客户台账，至少包含：

| 字段 | 用途 |
|---|---|
| customer_id | 客户内部编号 |
| contact | 联系方式，单独妥善保存 |
| license_id | 本次许可证编号 |
| plan | 套餐 |
| device_code | 当前绑定设备 |
| paid_at | 收款时间 |
| expires_at | 到期时间 |
| payment_reference | 转账备注或订单号 |

## 6. 续费

续费会验证旧许可证签名，保留套餐、设备和功能权限，并创建新的 `license_id`：

```bash
PYTHONPATH=src .venv/bin/python -m quant_lab.cli license-renew \
  --private-key "$HOME/quant-lab-license-admin/quant-lab.license-private.pem" \
  --license "$HOME/quant-lab-license-admin/customer_001-202608.qllicense" \
  --days 30 \
  --output "$HOME/quant-lab-license-admin/customer_001-202609.qllicense"
```

如果旧许可证尚未到期，续费天数从旧到期时间后顺延；如果已经到期，从当前时间重新计算。
输出文件拒绝覆盖，避免把旧授权链静默改写。

## 7. 验证许可证

```bash
PYTHONPATH=src .venv/bin/python -m quant_lab.cli license-inspect \
  --license "$HOME/quant-lab-license-admin/customer_001-202609.qllicense" \
  --public-key "$HOME/quant-lab-license-admin/quant-lab-public.pem"
```

命令只在签名有效时输出 payload。修改套餐、日期、设备码或功能列表都会使签名失效。

## 8. 商业门禁装配

源码开发默认放行：

```text
QUANT_LAB_LICENSE_ENFORCEMENT=development_disabled
```

测试商业模式：

```bash
export QUANT_LAB_LICENSE_ENFORCEMENT=required
export QUANT_LAB_LICENSE_PUBLIC_KEY_PATH="$HOME/quant-lab-license-admin/quant-lab-public.pem"
./scripts/dev.sh restart
```

商业模式下：

- GET/HEAD 查询继续可用；
- `/api/license/import` 始终允许；
- 其他 POST/PUT/PATCH/DELETE 必须有有效且包含 `research` 的许可证；
- `QUANT_LAB_LICENSE_ENFORCEMENT` 出现未知值时拒绝启动，不会因拼写错误回退到开发放行；
- 拒绝状态使用 HTTP 402，并返回中文原因与机器可读状态；
- CORS 仍允许本地 Web 正确展示授权错误；
- 到期或异常不删除 SQLite、Artifact、策略和报告。

当前商业安装包已把强制模式和公钥装配进 Nuitka 编译后的后端；客户不能通过环境变量
切回开发放行模式。Windows Authenticode 和 macOS Developer ID 公证仍需在正式扩大销售
前完成。只设置一个用户可修改的环境变量不构成最终商业保护。

## 9. 换机与时间异常

换电脑后设备码会变化，旧许可证不能使用。第一版由商家核对客户和付款记录后，使用新
设备码重新签发；旧许可证因绑定旧设备自然失效，但无法远程从旧电脑删除。

软件保存最后一次正常运行时间。系统时间向过去回退超过 24 小时时暂停新研究，但仍允许
查看和导出。该检测只用于阻止明显回拨，不应声称能防御所有本地篡改。

## 10. 未来迁移账号订阅

当前 payload 已保留 `customer_id`、`license_id`、`plan`、`features`、`device_code` 和
到期时间。以后增加账号服务器时，可直接迁移为：

```text
Customer
  → Subscription / Entitlement
  → Device
  → Signed offline lease
```

客户端仍可验证短期签名许可证，只把“人工签发”替换为“服务器签发”。历史研究数据和
本地数据库不需要迁移到云端。
