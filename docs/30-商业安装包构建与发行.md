# 商业安装包构建与发行

状态日期：2026-08-03

## 1. 当前支持范围

商业安装包采用“源码仓库构建、客户只获得安装制品”的方式：

| 平台 | 原生构建环境 | 输出 |
|---|---|---|
| macOS ARM64/Intel | 对应架构的 macOS runner | `.dmg`、`.zip`、`.sha256` |
| Windows x64 | GitHub Actions `windows-2022` | `-setup.exe`、`.zip`、`.sha256` |

Python 后端、Worker 和 Local Connector 使用 Nuitka standalone 编译。Next.js 使用
standalone 生产输出，并随安装包放入固定 Node 运行时。商业运行器强制启用离线许可证，
客户不能通过环境变量切回开发放行模式。

Windows 客户数据位于：

```text
%LOCALAPPDATA%\QuantResearchLab
```

macOS 客户数据位于：

```text
~/Library/Application Support/QuantResearchLab
```

安装、升级或卸载不会把客户数据库、行情、策略和报告放进程序安装目录，也不会在卸载时
删除客户研究数据。安装包不捆绑 Freqtrade、商业许可证签发私钥、客户 `.qllicense`、
SQLite、DuckDB、Parquet、行情数据或既有策略。

## 2. 只允许手动云端构建

两个工作流都只有 `workflow_dispatch`，没有 `push`、`pull_request`、版本标签或定时触发：

```text
.github/workflows/build-commercial-macos.yml
.github/workflows/build-commercial-windows.yml
```

普通提交和 Git Tag 不会自动消耗 Actions 额度。正式构建步骤：

1. 确认目标提交已推送到私有 GitHub 仓库；
2. 打开 GitHub 仓库的 `Actions`；
3. 选择 `Build commercial Windows package` 或
   `Build commercial macOS package`；
4. 点击 `Run workflow`；
5. 输入要显示在安装包中的版本号；
6. 构建结束后及时下载 Artifact；
7. 用同目录 `.sha256` 核对制品。

Artifact 默认只保留 7 天，避免商业包长期占用 Actions 存储。它不是永久发布仓库；下载
后应放入商家自己的加密发行归档。

## 3. GitHub 只配置授权公钥

仓库 Secret 名称固定为：

```text
QUANT_LAB_LICENSE_PUBLIC_KEY_B64
```

macOS/Linux 可生成单行 Base64：

```bash
base64 < "$HOME/quant-lab-license-admin/quant-lab-public.pem" | tr -d '\n'
```

把结果放到 GitHub 仓库：

```text
Settings → Secrets and variables → Actions → New repository secret
```

公钥可进入安装包，不具备签发能力。以下内容绝不能放进 GitHub Secrets、仓库、构建
Artifact 或客户安装包：

```text
quant-lab.license-private.pem
客户许可证台账
客户联系方式
客户 .qllicense
```

## 4. Windows 构建内容

Windows 工作流会：

1. 在干净的 `windows-2022` x64 runner 安装锁定依赖；
2. 运行商业授权、商业运行器和 Run 身份测试；
3. 构建 Next.js standalone；
4. 下载 Node `24.10.0` Windows x64 官方 ZIP 并校验固定 SHA256；
5. 使用 Nuitka 编译商业运行器；
6. 使用 GitHub runner 自带的 Inno Setup 6 生成当前用户级安装程序；
7. 同时生成便携 ZIP 和 SHA256 文件；
8. 上传 7 天 Artifact。

Windows 安装目标默认是：

```text
%LOCALAPPDATA%\Programs\Quant Research Lab
```

不要求客户提供管理员权限。启动后浏览器访问本机 Web Studio；API 和 Web 仍只监听
`127.0.0.1`。

当前 Windows MVP 尚未使用 Authenticode 商业代码签名，客户可能看到“未知发布者”或
SmartScreen 提示。适合内部 QA 和少量明确知情的付费试点；正式扩大销售前应购买代码
签名能力并给最终 `setup.exe` 和主程序签名。

## 5. macOS 构建内容

macOS 工作流同样是纯手动触发，生成 `.app`、`.zip`、`.dmg` 和校验文件。当前 MVP 使用
ad-hoc codesign，不等同于 Apple Developer ID 签名和 notarization。正式扩大销售前应
完成 Developer ID 签名、公证和 stapling。

## 6. Actions 额度与成本

根据 GitHub 官方文档在 2026-08-03 展示的标准 GitHub-hosted runner 规则：

| 账户计划（私有仓库） | 每月包含分钟 | Artifact 存储 |
|---|---:|---:|
| GitHub Free 个人账户 | 2,000 分钟 | 500 MB |
| GitHub Pro | 3,000 分钟 | 1 GB |
| GitHub Free 组织 | 2,000 分钟 | 500 MB |
| GitHub Team | 3,000 分钟 | 2 GB |

每个仓库另有 10 GB Actions cache 包含量。标准 runner 用于公开仓库通常免费，但本商业
项目不能为了省额度把源码仓库改成公开。

额度按 Job 实际运行时间累计；失败后重新运行会再次计时。当前超出包含量后的基准价格为：

| runner | 价格 |
|---|---:|
| Linux 2-core x64 | 0.006 美元/分钟 |
| Windows 2-core x64 | 0.010 美元/分钟 |
| macOS M1/Intel | 0.062 美元/分钟 |

官方规则和价格可能调整，正式构建前以
[GitHub Actions 计费文档](https://docs.github.com/en/billing/concepts/product-billing/github-actions)
为准。

Nuitka 首次构建会分析大量依赖，时间明显长于普通测试。建议：

- 普通提交只在本地运行检查；
- 只有准备给客户的新制品才手动运行完整 Actions；
- 同一平台不要同时重复点击；
- Artifact 下载后删除或等待 7 天自动过期；
- 在 GitHub Billing 中设置预算和 90%/100% 提醒；
- 未绑定付款方式时，免费额度用完后工作流通常会被阻止，而不是无限产生费用。

## 7. 本地构建

macOS：

```bash
make commercial-macos \
  LICENSE_PUBLIC_KEY="$HOME/quant-lab-license-admin/quant-lab-public.pem"
```

Windows PowerShell/Git Bash 环境准备完成后：

```text
make commercial-windows LICENSE_PUBLIC_KEY=C:/安全目录/quant-lab-public.pem
```

Windows 正式制品仍建议由 Actions 的干净 Windows runner 生成。本地 Windows 构建主要用于
排错；macOS 不能直接生成可靠的 Nuitka Windows 安装包。

## 8. 发布前验收

- 构建来源是明确的干净提交；
- 公钥指纹与商家长期公钥一致；
- 安装包内没有 `.qllicense`、私钥、SQLite、DuckDB、Parquet 和客户数据；
- 新设备首次启动能显示设备码；
- 导入正确许可证后可以创建研究；
- 错设备、过期和篡改许可证均进入只读；
- `--stop` 能正常停止 API、Web、Worker 和 Connector；
- 卸载后客户数据目录仍存在；
- `.sha256` 与下载制品一致；
- Windows SmartScreen/macOS Gatekeeper 的当前签名边界已向试点客户说明。
