# 个人量化策略研究工作法

## 一、项目定位

本项目服务个人量化研究者，不照搬机构级重型因子工厂。核心工作模式是：

> 策略优先，因子随策略研究自然沉淀。

研究从一个可描述、可形式化、可回测的策略想法开始，不要求先积累大量因子再产出
策略。因子库、失败库和策略库都是研究过程中自然形成的副产品与长期资产，不是每天
盲目挖掘、追求数量的目标。

本项目不承诺“不亏”，也不承诺未来盈利。研究结果只说明某个明确版本在指定数据、
成本和执行假设下的历史表现与风险证据。

## 二、策略收录与研究流程

### 1. 收录原始想法

用户可以提供：

- 自然语言描述；
- TradingView Pine Script；
- 公开策略或开源代码；
- 书籍、文章、课程、播客或视频中听到的规则；
- 对现有策略的一个明确改进想法。

收到策略后，先保存原始来源、收录日期、原始描述、适用市场、品种、周期、方向和
所有模糊点。原始材料只追加新版本，不因后续理解变化而覆盖。

### 2. 形式化并冻结基准

把原始描述转成无歧义规则，明确：

- 指标和数据的计算时间；
- 入场、出场、止损、止盈和失效条件；
- 仓位、并发持仓、资金分配和风险上限；
- K 线内触发顺序与同根冲突的保守处理；
- 手续费、滑点、资金费率、精度、最小金额和成交限制；
- 不明确处采用的解释以及备选解释。

形式化后，先建立“原样基准版本”并冻结。禁止一开始就为了得到盈利结果而改规则、
筛市场或调参数。若原始策略表现差，也必须如实保存基准结果。

### 3. 一次验证一个假设

每次优化只能对应一个可陈述的改进假设，例如“趋势过滤能减少震荡期亏损”或“波动率
仓位能降低尾部回撤”。实验必须和冻结基准对照。多个组件同时加入时，必须做消融测试，
分别回答每个组件是否提供稳定的样本外增量。

禁止为了让回测盈利而无限调参。每次研究任务都应事先写明搜索空间、计算预算、停止
条件和验收门槛。

### 4. 保存全部证据

每个版本和实验必须保存：

- 策略/组件版本与代码版本；
- 数据来源、版本、市场、品种、周期和时间范围；
- 训练、验证、锁定测试切分；
- 参数、费用、滑点、资金费率和执行假设；
- 随机种子、命令、日志和结果路径；
- 基准、样本外、Walk-forward、成本和压力测试结果；
- 失败原因、污染情况、结论和下一步假设。

失败实验不得删除或隐藏，以防止重复踩坑、事后挑选结果和选择性汇报。

## 三、沉淀四层长期资产

### 1. 原始策略档案

保存原始来源、原文/Pine Script、收录日期、版权或许可证信息、初始理解和模糊点。
原始档案是追溯依据，不随优化覆盖。

### 2. 不可覆盖的实验记录

每次运行在 `experiments/runs/` 建立独立 manifest 和结果目录。成功、失败、无效和
污染实验同等保留。

### 3. 可复用研究组件

只有经过证据支持的因子、过滤器、仓位、风控和执行组件才进入组件库。组件必须保留
来源、定义、最早可获知时间、适用条件和失效证据。

### 4. 策略最终状态与失效条件

策略可以处于 `inbox`、`formalized`、`baseline`、`candidate`、`validated`、
`dry_run`、`production`、`degraded`、`retired` 或 `rejected`。状态可通过目录、注册表
或 manifest 表达，不为了状态名称而重构已有目录。

进入 `production` 必须获得人工明确批准。策略必须记录适用市场状态、监控指标、退化
阈值、停用条件和重新验证要求。

## 四、工作节奏

### 每日自动任务

- 检查数据缺失、重复、延迟、异常价格和版本变化；
- 检查已有因子健康度、衰减和相关性异常；
- 对已有策略运行滚动样本外或回归验证；
- 监控回撤、滑点、成交、信号和回测偏差；
- 生成日报和风险提示。

每日任务不得重新调优生产参数，不得自动发明策略或因子，不得自动晋升生产状态。

### 出现新想法时

为新策略或新假设创建独立研究任务，先收录、形式化并确定验收门槛，不混入日常监控。

### 每周或按研究任务

- 研究候选因子、过滤器、仓位和风控组件；
- 执行对照与消融；
- 运行样本外、Walk-forward、成本和压力测试；
- 更新候选、验证、退化或拒绝建议；
- 生成可审阅的研究报告。

### 定期组合复核

评估策略组合的收益来源、相关性、共同尾部风险、容量、换手和衰减。组合收益不能掩盖
单个策略已失效的事实。

## 五、因子与理论的处理原则

因子不是完整策略。只有把因子加入冻结基准后，产生稳定、可解释、扣除成本后的样本外
增量，才值得保留。

每个因子至少记录：

- 来源、公式、代码版本和最早可获知时间；
- 数据依赖、方向、周期、标准化和缺失处理；
- 费用、滑点、换手、衰减、容量和相关性；
- 适用市场、品种、周期、市场状态和失效状态；
- 基准增量、样本外、Walk-forward、消融和压力测试证据。

别人的因子只能作为 `candidate`。必须在自己的交易所、品种、周期、费用和滑点下重新
验证。少量相互独立、稳定、可解释的因子优先于大量高度相关的因子。

缠论、价格行为、波浪等理论先记录概念、版本、争议、确认时间和可观测信息，再进行
形式化、标注、因子化和验证。禁止用只有事后才能确认的结构回填历史信号。

## 六、验收与防过拟合

1. 原样基准先冻结，再允许优化。
2. 时间序列按训练、验证、锁定测试的顺序切分，禁止随机打乱。
3. 查看锁定测试后再修改策略，必须标记测试集污染，并建立更新的锁定区间。
4. 不以历史净利润最高作为唯一选择标准。
5. 必须扣除手续费、滑点、资金费率并模拟执行限制。
6. 参数选择稳定平台，不选择孤立的最佳尖峰。
7. 候选策略通过样本外、Walk-forward、敏感性和压力测试后，才可进入模拟盘。
8. 模拟盘与回测差异必须可解释；生产晋升必须人工批准。
9. 任何报告都不得承诺不亏或未来盈利。

## 七、第一阶段轻量实施范围

第一阶段保留：

- 统一数据规范和成本模型；
- 可重复、可追溯的回测；
- 策略版本和实验注册；
- 样本外、Walk-forward 和压力测试；
- 简单因子标签与可复用组件库；
- 报告、模拟盘和生产晋升门禁。

第一阶段暂不启用：

- 每日自动发明新因子或新策略；
- 大规模机器学习和强化学习；
- 上千组合的暴力搜索；
- 自动生产晋升；
- 自动实盘、自动增加杠杆或自动放大资金；
- 复杂数据湖和机构级基础设施。

只有用户明确提出需求，并且已有研究规模证明必要时，才评估增加这些能力。

## 八、策略进入项目的最小动作

1. 复制 `configs/strategy-intake.example.yaml` 创建收录记录。
2. 原始 Pine Script 放入 `strategies/pine/`；自然语言或其他来源可先归档到
   `strategies/inbox/`。
3. 明确模糊点并形成无歧义规则。
4. 建立和冻结原样基准版本。
5. 创建实验 manifest，运行基准和预先定义的验收流程。
6. 每个改进假设创建新版本，不覆盖原始基准。

## 九、Fail-fast、组件和市场状态

个人研究优先尽早杀死不可行的完整策略，而不是尽早扩大计算。标准顺序为：

`correctness → fast screen → viability → cheap sensitivity → regime/Pine → full validation/locked/full stress → dry-run`

失败策略保留 `StrategyOutcome=rejected`。如某个单一组件仍呈现样本外增量，
可带来源策略、lineage、市场、指标和失败条件保留为 `diagnostic_improvement`
或 `component_candidate`，但不得自动变成 validated factor。

Regime detector 必须只使用交易决策时已可观测数据，记录 detector version、
适用/条件/禁用/未知状态和转换政策。90 日结果只能称 screening 或
insufficient history。自然语言/Python 策略的完整 Pine 对账后移到 viability
通过后；Pine 来源在早期只做语义、repainting、多周期和少量 golden trades 检查。
