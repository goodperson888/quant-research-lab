# 存储治理与保留策略

## 1. 权威分类

机器可读政策位于 `configs/storage-policy.yaml`，分为：

- `authoritative`：原始数据、规范 Parquet、manifest、实验事实与报告；
- `rebuildable`：DuckDB、Freqtrade 运行时数据、Web build 与本地缓存；
- `archiveable`：在摘要、lineage 和 checksum 永久保留后，可由人工决定归档的
  非关键 Trial 完整 trades/equity。

政策固定 `automatic_deletion=false`。本轮不删除、迁移或重写任何旧证据。

## 2. Trial 保留级别

所有 Trial 永久保留：指标、manifest、状态、参数、失败原因、代码/数据版本、
成本、种子和日志引用。完整 trades/equity 默认保留于：

- 冻结 baseline；
- 关键 candidate；
- 进入 locked test 的少量候选；
- 用户或研究计划显式指定的对象。

其他 Trial 只能在永久摘要和 checksum 完成后标记 archiveable，不得自动删除。

## 3. 避免小文件爆炸

Trial metrics 通过 `TrialMetricsSink` 预留批量 Parquet 接口，目标按
`experiment_plan_id/year/month` 分区，最小批量 500 行、目标批量 5,000 行。
本轮不迁移旧产物，也不为每个 Trial 创建几十个指标小文件。

## 4. 只读报告

```bash
PYTHONPATH=src .venv/bin/python -m quant_lab.cli storage-report
```

API 为 `GET /api/storage/report`。该功能只扫描 storage policy 中审阅过的项目相对
目录，不接受调用者传入任意路径。

2026-07-22 年度数据扩展后：

- storage policy 覆盖约 18,000 个文件、约 877 MiB；精确文件数会随可重建缓存变化；
- `data/raw` 约 13.2 MiB，564 个文件；
- `data/processed` 约 24.3 MiB，135 个文件；
- Freqtrade 可重建数据约 6.3 MiB；
- 主要文件数警告来自 `.cache` 和 `.next`，它们都是 rebuildable；
- raw 的小文件比例警告主要由 Binance 官方 OI 日包导致，不应为清除警告而
  改写或合并原始官方归档。

## 5. 备份优先级

1. raw、processed、manifest、Run 事实、报告和 SQLite；
2. 策略源码、配置、规则和 Git 远端；
3. DuckDB/Freqtrade runtime 可从权威 Parquet 重建；
4. `.cache`、`.next` 不是研究证据。

建议至少“本机 + 外接介质 + 异地加密副本”，并定期验证 Parquet 可读、
SQLite 一致和 DuckDB 可重建。

## 6. 图表与两年计划

Studio 图表 API 只通过已登记的 Run Bundle 定位 manifest，再读取其中白名单
`equity*.parquet` Artifact。调用方不能提交任意绝对路径；序列确定性降采样后返回，不写入
SQLite 或 append-only audit。多数参数 Trial 当前没有独立 equity Artifact，页面必须显示
不可用原因，不能从汇总指标伪造 Top Trial 曲线。

两年扩展当前只有禁用计划模板。真正下载前必须先检查磁盘并创建独立 data version、manifest
和质量报告；raw 只追加，不覆盖现有一年数据。滚动验证每个 fold 的 manifest、关键指标和
失败原因永久保留，完整 trades/equity 仍按 Baseline、关键 Candidate 和显式 retain 规则。
