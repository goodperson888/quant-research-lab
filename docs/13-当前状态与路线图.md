## 下一步优先级

### P0：选择新的单一假设或新策略

1. 不重跑 rejected 版本；由用户提供新策略，或对现有 baseline 提出一个新的可证伪假设；
2. 使用当前 Pipeline Profile，先做 correctness 和 fast screen；
3. 只有 viability 通过才进入完整 Pine/第二引擎对账、regime、full validation 和 full stress；
4. 所有审批必须引用精确 subject ID。

### P1：第二引擎与样本外证据

1. 将一个 viability 通过的版本实现为 Freqtrade `IStrategy`；
2. 选少量 golden trades 与 Native engine 逐笔解释差异；
3. 定义训练、验证和锁定测试区间；
4. 运行 Walk-forward、费用/滑点、延迟、漏单和参数扰动。

### P2：组件与 Regime

1. 只对已有明确 ablation lineage 的组件做廉价 triage；
2. 组件最多先到 diagnostic/component candidate，独立样本外证据后才讨论升级；
3. 用 1h 已收盘标签形成 screening 级 regime 报告；
4. 候选通过门禁后再准备 dry-run。

### P3：数据扩展

1. 在出现可行候选后补更长历史和 OKX 对照；
2. 明确处理 funding/mark/index/OI 缺口，不填零；
3. 只在单机架构出现可测量瓶颈后评估更重服务。

## 第一阶段完成标准

以下条件全部满足才算完成：

1. 至少一个真实策略 baseline 的时点、成本和代表交易可解释；
2. 同一版本通过配置化 viability，而非仅“少亏”；
3. Native 与 Freqtrade/参考平台的关键交易差异可解释；
4. 数据、代码、参数、成本、切分、种子和结果进入不可变 manifest；
5. funding、滑点、费用和关键执行限制没有静默忽略；
6. 至少完成一次时间顺序样本外或 Walk-forward；
7. 完成 cheap sensitivity，并在 viability 后完成 full stress；
8. 失败、污染、组件 lineage 和 Regime 限制完整保留；
9. 策略最多达到 `validated` 或准备 `dry_run`；
10. 没有自动实盘、自动加杠杆、自动生产晋升或盈利承诺。

第一阶段完成只说明研究流程和证据达到预设标准，不构成投资建议，也不保证未来盈利。
