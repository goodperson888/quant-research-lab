# 回测与验收规范

## 回测必须模拟

- Maker/Taker 手续费；
- 滑点和下单延迟；
- 最小金额、数量精度和部分成交；
- 资金费率、杠杆和强平；
- 限价单未成交；
- 同一根K线同时触发止盈止损的保守处理。

## 必看指标

- 总收益和年化收益；
- 最大回撤和回撤持续时间；
- Sharpe、Sortino、Calmar；
- Profit Factor 和单笔期望；
- 交易次数、胜率、盈亏比；
- 资金利用率和换手率；
- 手续费占毛利润比例；
- 连续亏损和尾部损失；
- 月度、季度、资产和市场状态分解；
- 样本内外差距。

## 验收原则

- 不设置脱离策略频率和资产特征的通用收益阈值。
- 最大回撤、最小交易数和费用假设必须在项目配置中明确。
- 选择稳定参数区域，不选择孤立最高点。
- 最终测试集锁定，只在候选策略冻结后使用。
- 若查看最终测试结果后修改策略，该测试集立即视为污染。

## 独立门槛

- `correctness` 只证明数据时点、代码、成本和代表交易可解释；
- `incremental` 只证明单一改动相对冻结 baseline 有增量；
- `viability` 独立检查 validation 净收益、Profit Factor、期望、最小交易数和最大回撤；
- `robustness`、`locked_test` 和 `dry_run` 各自保留独立结论和证据。

完整策略只有通过当前 profile/market/objective 的 viability 才能成为正式
strategy candidate。“只比 baseline 少亏”必须标记为 `diagnostic_improvement`，
必要时将局部 entry/filter/exit/risk/execution 单独保留为组件候选。

Freqtrade `lookahead-analysis`/`recursive-analysis` 只属于 correctness 诊断，不提供收益
验收结论。诊断不得使用 rejected 策略或 locked test；外部引擎不可用时必须保留 blocked/
unsupported 原因，不影响 Native Engine 核心流程。
