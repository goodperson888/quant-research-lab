# 阶段2研究门禁与资源预算

状态日期：2026-07-22

## 1. 目标

阶段2把三类容易被对话绕过的约束落到后端：Regime 诊断与正式验证分离、研究会话和
Worker 都有预算、Freqtrade 正确性诊断只能通过固定白名单运行。它不运行新的真实策略，
不查看 locked test，不改变已有 rejected 证据，也不增加实盘能力。

## 2. Regime 双模式

`regime_diagnostic` 可在 viability 前运行，用于廉价定位策略在哪些已知、可观测的市场
状态中失效。其结论只能是 diagnostic、`screening` 或 `insufficient_history`，不能晋升
策略或组件，365 日数据也不能把诊断模式改称正式 validation。

`regime_validation` 只有在同一 `subject_id` 已存在 `gate_name=viability` 且
`status=passed` 的 GateEvaluation 时才可创建 Job 或写入正式记录。API、Application
Service、Pipeline Service 和 Worker 都检查这一关系。两种模式都要求 ex-ante label；
禁止用未来收益定义状态。

SQLite schema v4 为每条 RegimeValidation 保存 `mode` 和
`viability_gate_result_id`。旧记录迁移后保守标记为 `regime_diagnostic`，避免把历史
screening 追溯升级。

## 3. Freqtrade 正确性诊断

`correctness_diagnostic` Job 只允许 `lookahead-analysis` 和 `recursive-analysis`。Runner
通过 `scripts/freqtrade.sh` 组装固定参数列表，不使用 Shell 字符串，不接受绝对路径；
策略文件仅允许位于批准的 Freqtrade 策略目录，配置仅允许位于 `configs/`。

诊断可在 viability 前使用，但必须满足：策略不是 rejected、`locked_test_used=false`、
没有 `trade`、没有 Key。输出写入项目相对的 manifest、JSON report、Job log 和 audit
event，并明确标注 `correctness_only_no_strategy_performance_claim`。客户未安装 Freqtrade
或命令失败时，Job 失败并保留 unsupported/failed 证据；Native Engine 不受影响。

本阶段只用 fixture 验证命令边界和解析，不运行当前 rejected 策略，也不声称完成真实
lookahead/recursive 研究结论。

## 4. ResearchSession 预算

默认机器配置位于 `configs/research_budgets/default.yaml`：

- `max_hypotheses`；
- `max_trials_total`；
- `max_compute_minutes`；
- `max_locked_test_uses`；
- `require_user_approval_for_new_hypothesis`。

创建会话时在 SQLite 建立 ResearchBudget。批准 ExperimentPlan 会占用一个 hypothesis；
创建 parameter-search Job 会按计划的 max Trials 和时间预算预留会话资源；任何声明使用
locked test 的 Job 必须提供 session ID 并占用一次额度。超限动作不创建或不继续运行，
并追加 `research_budget.blocked` 事件。ExperimentPlan 自己的预算继续保留，两级预算同时
生效。

## 5. Worker 资源预算

`configs/workers/local.yaml` 定义：

- `max_rss_mb`；
- `max_concurrent_trials=1`；
- `max_job_minutes`；
- `parquet_batch_rows`；
- `kill_on_memory_limit`。

Worker 在单次与 watch 模式下都使用定时资源检查中断超时或越过 RSS 上限的 Handler，Job 标记 failed，
日志和 audit 保存 elapsed time、peak RSS、策略 ID 与失败原因。成功 Job 同样报告资源指标。
当前并发固定为 1；`parquet_batch_rows` 是未来批量 Trial sink 的协议目标，不表示已经实现
通用参数优化器。

## 6. API 与 Studio

新增只读/受限接口：

- `GET /api/research-budget/default`；
- `GET /api/research/sessions/{session_id}/budget`；
- `GET /api/worker/resource-policy`；
- `POST /api/correctness-diagnostics/jobs`；
- Regime API 增加 `mode` 和可选 `viability_gate_result_id`。

Studio 显示会话预算已用/剩余、Regime mode 和 viability 关系；Settings 显示 Worker
资源上限。OpenAPI 仍没有 live、trade、Shell 或 credential 端点。
